# ChinaPlanet Office Expenses

Standalone module at `custom/chinaplanetofficeexpenses/`, owning its descriptor, translations, menu and default-denied draft/admin/read/manage-access rights. Its only declared dependency is native `modExpenseReport`; ChinaPlanet Operations is not required.

This is the local standalone refactor, not an activated release. The previously deployed backup pilot is unchanged. See `docs/REPORTS/M119_STANDALONE_MODULE.md`.

## Runtime and compatibility

- Canonical route: `/custom/chinaplanetofficeexpenses/index.php`.
- The old `/custom/chinaplanetoperations/office_expenses/index.php` directly includes the canonical entry, preserving method, query, POST and uploads.
- Old PHP class paths use `require_once` compatibility includes, with one canonical implementation.
- Direct entry requires standalone enablement, active internal identity and its draft right or native administrator status. Existing native expense-report rights, pilot identity/entity/office restrictions, ownership and CSRF checks remain intact.
- Staff mode defaults off. Explicit native capabilities plus audited per-branch memberships enforce own/branch visibility when enabled; the approved pilot administrator remains the bootstrap owner. No rights are granted by copying source; financial posting stays disabled.

## Data preservation

Existing `cpo_oe_*` tables, schema versions/manifests, identifiers and private storage paths remain unchanged. Configuration is still `/var/lib/chinaplanetos-office-expenses/pilot.json`; private receipts remain in the existing private receipts directory outside the web root. No table rename or data copy is required.

`init()` and `remove()` pass no domain SQL. They do not install/drop draft tables or delete receipts. Explicit readiness/migration code retains its existing checks; module activation is not a migration.

Old schema/static assets remain for compatibility and historical contracts. Do not develop a second domain implementation in the legacy folder.
