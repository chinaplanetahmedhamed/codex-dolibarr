## Implemented correction: transaction confirmation

`OfficeExpenseNativeDraftStore` previously ignored rollback acknowledgement, repeatedly rolled back while the native counter remained positive, and attempted recovery by reading the same connection. Native `DoliDB::rollback()` resets `transaction_opened` to zero **even if its SQL rollback fails**. Consequently an uncommitted source/audit could be read as a saved draft; a handle whose counter never moved could loop. A lost commit response also lacked a safe distinction from an ordinary write error.

The store now requires acknowledged begin at depth1 and acknowledged commit at depth0. On failure, it attempts one owned outer rollback only. Only an acknowledged rollback ending at depth0 permits same-connection retry lookup. Uncertain begin/commit/rollback retires that handle for all draft reads/writes and for other/new store instances sharing it. PHP7.4 `WeakReference` tracking avoids retaining failed handles in a long-lived process. The factory/caller must discard the uncertain connection and use a **fresh physical connection**, not reconstruct a wrapper around it or merely reset its counter. This guard is scoped to this draft-store class; it does not claim to disable other ERP users of a shared handle.

No evidence is deleted and no success is reported for an unknown outcome. If commit actually succeeded but its response was lost, a fresh connection verifies the immutable source/audit and the same scoped key recovers the **one existing source**. A confirmed rollback permits a clean retry. Caller-owned transactions continue to be refused without rollback or commit.

Modified implementation: `custom/chinaplanetoperations/office_expenses/class/OfficeExpenseNativeDraftStore.php`.
