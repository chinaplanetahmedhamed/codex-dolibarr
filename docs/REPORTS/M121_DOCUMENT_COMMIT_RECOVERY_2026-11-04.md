If a caller owns an outer transaction, the service neither closes, commits, resets nor rolls it back. Operations owns the task wrapper's outer transaction. Document mutation catches uncertain startup and an unconfirmed outer upload commit, preserving the saved document identity and refusing ordinary retry handling. Its document-specific startup path avoids the legacy unchecked caller rollback. A display hydration failure after acknowledged upload reports committed only when there was no original caller-owned outer transaction; otherwise it remains unknown. Neither path unlinks files or rolls back an already acknowledged upload. The API returns503 with AR/EN review/no-repeat wording, records internal reconciliation IDs/key/fingerprint where available, and performs no later business query or native rendering. Authentication/CSRF still belongs to the native bootstrap.
