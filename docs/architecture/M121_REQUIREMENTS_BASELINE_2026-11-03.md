# متطلبات العمل — استلام التعليمات الكاملة
3 نوفمبر 2026. المصدر: نص أحمد حامد الكامل في المحادثة؛ هذا ملخص تتبّع وليس نسخة حرفية.
- تحسين Dolibarr القائم كمنتج متكامل؛ لا ERP بديل ولا وحدات منعزلة.
- واجهة مالية بسيطة: مقبوض/مدفوع/لنا/علينا/متاح/قريب/متأخر؛ منطق معقد داخلي دون إجبار الموظف عليه.
- كشف عميل جامع للمشاريع، وكشف مورد جامع للعملاء/المشاريع؛ المورد كل مستفيد من الدفع.
- الواقعة المالية تدخل مرة واحدة؛ amount/currency/date/payer/payee/funding/method/evidence وعلاقات المشروع/المهمة وتقسيم عدة مشاريع.
- النقد != الالتزامات != ائتمان الفاتورة. لا تخصيص تلقائي لإيداع عميل لمورد؛ التمويل قد يكون من الشركة.
- Open افتراضي وClosed/All History/فترة مخصصة؛ لا حذف؛ task Done لا يسوي دينًا.
- Customer Workspace -> Projects -> Tasks؛ Board مركز اليوم، والوحدة المختصة مصدر التفاصيل والحالات.
- العنوان البشري واسم العميل بارزان، المرجع صغير وباقٍ للبحث والتتبع؛ لا تغيير IDs.
- Compact/Comfortable وكثافة وهوامش وخطوط وألوان مريحة وRTL/LTR والهاتف؛ مقارنة native Dolibarr بنفس zoom/viewport.
- أولوية كاملة العرض بنص/رمز، ظاهرة دون فلتر؛ لوحة اليوم للمفتوح والعاجل والمتأخر والمستحقات والشحن والمستندات والـblocked.
- ربط الإنتاج والفحص والشحن والدفع والمستندات وCargoX/DHL؛ quick action يحفظ في المصدر؛ رابط سجل دقيق وreturn context.
- دمج Docs.chinaplanet.org الحالي وقوالبه في تجربة ERP والمشروع/الشحنة؛ CI/PL/BL/COO/booking/slips/فحص/صور/CargoX/DHL.
- تنبيهات مناسبة وتجنب المكتمل/المسوّى؛ الصلاحيات والعزل وCSRF والمعاملات والتدقيق ومنع التكرار.
- كل وحدات ERP والتكاملات في custom داخل المشروع الرئيسي؛ missions-list.md وresources.md؛ سجل Drive والدليل القائم يعاد استخدامهما.
- تقرير معمارية وخطة قبل التغيير الكبير. المراحل: تدقيق، مالية، UI، تكامل، لوحة وتنبيهات، اختبار شامل.
- اختبار عميل ومشروع وثلاثة موردين وحاوية وإيداع ودفعات وفحص وشحنة ومستندات وCargoX وDHL؛ تاريخ وإعادة فتح ومورد مشترك وتمويل شركة.
- التفويض اللاحق: Work يتخذ القرارات ويجري النسخ والنشر والاختبار والبيانات والحسابات التجريبية على backup-erp دون موافقات جزئية. الإنتاج ممنوع تمامًا.
