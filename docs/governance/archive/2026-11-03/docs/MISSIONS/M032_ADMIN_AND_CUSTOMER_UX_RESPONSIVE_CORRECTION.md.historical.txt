## الهدف التجاري

جعل واجهة موظفي الشركة وبوابة العميل أوضح وأسرع وأكثر اتساقًا، مع إزالة المصطلحات المضللة وتحسين استخدام الهاتف دون تغيير البيانات أو المحاسبة أو الصلاحيات.

## سياق النظام الحالي

- غلاف الإدارة المخصص يعرض `Portal` و`Files` ووسم `LIVE` غير المقيّد، ويُظهر زر إنشاء شحنة في كل الصفحات.
- صفحات العميل تستخدم غلافًا مشتركًا، لكن بعض عناصر النماذج والجداول لا تتكيف جيدًا عند عرض الهاتف.
- فحص UX السابق أثبت أن الملكية والبيانات ليست موضوع هذا التصحيح؛ المطلوب هنا عرض وتنقل وتجاوب فقط.
- شجرة العمل تحتوي تعديلات M030/M031 معتمدة؛ يجب البناء عليها وحمايتها وعدم تنظيفها أو استبدالها.

## النطاق

### أولًا: الإدارة

1. توحيد أسماء وروابط التنقل: معاينة بوابة العميل، المستندات، التقارير، ومكتبة SOP.
2. استبدال `LIVE` بوسم بيئة متحكم فيه ووقت توليد منفصل وواضح.
3. إبقاء زر إنشاء الشحنة بارزًا فقط في الصفحات التشغيلية المرتبطة بالشحن.
4. تحسين استجابة غلاف الإدارة وأهداف اللمس للكمبيوتر واللوحي والهاتف.

### ثانيًا: بوابة العميل

5. توضيح الحساب المالي مع إبراز الوصول الآمن للملف الشخصي.
6. إصلاح عناصر البحث والتصفية والجداول/البطاقات عند 390px و430px دون معالجة كل مقاس منفصلًا.
7. فرض أهداف لمس لا تقل عن 44px على الإجراءات الرئيسية المتأثرة.
8. اختبار الصفحات المتأثرة ببيانات حقيقية محلية وباتجاهي RTL/LTR قدر الإمكان.

### التطابق

9. تحديث سجل `PORTAL_PARITY.md` وترك تطبيق الهاتف `PENDING`؛ لا تعديل لكود التطبيق في هذه المهمة.

## خارج النطاق

- لا تغيير في Orders & Support.
- لا تعديل لتطبيق الهاتف أو API.
- لا تغيير في قواعد الأعمال أو المحاسبة أو قواعد البيانات أو الصلاحيات.
- لا تعديل لملفات Dolibarr الأساسية.
- لا Git commit/push ولا نشر إلى backup-erp أو الإنتاج.

## المكونات المطلوب فحصها

- `chinaplanetcustomercenter/lib/admin_shell.lib.php`
- `chinaplanetcustomercenter/lib/portal.lib.php`
- ملفات CSS المشتركة للإدارة والبوابة.
- قائمة الشحنات والصفحات التي تستخدم الغلافين المشتركين.
- مصدر إعدادات Dolibarr للثوابت العامة دون إنشاء إعداد جديد.

## المعمارية وتدفق البيانات

- تظل دوال الغلاف المشتركة مصدر الحقيقة للتنقل والهوية البصرية.
- وسم البيئة يقرأ ثابت Dolibarr اختياريًا، مع قيمة محلية آمنة لا تدّعي الإنتاج عند غياب الإعداد.
- لا تُنسخ بيانات الإدارة إلى العميل؛ التغييرات عرضية فقط.
- التجاوب يعتمد Grid/Flex و`minmax()` و`overflow-wrap` ونقاط تحول قليلة مرتبطة بالمحتوى.

## الصلاحيات والرؤية

- لا تغيير في التحقق من `entity` أو `fk_soc` أو الحقوق.
- لا إضافة لأي بيانات مورد أو تكلفة أو هامش أو ملاحظات/ملفات داخلية إلى البوابة.
- الروابط الجديدة تستخدم المسارات الحالية وصلاحياتها الحالية.

## أثر قاعدة البيانات والمحاسبة والإعدادات

- **قاعدة البيانات:** لا يوجد.
- **المحاسبة:** لا يوجد.
- **الإعدادات/حالة الوحدات:** لا تغيير. قراءة ثابت اختياري فقط.

## المتطلبات الوظيفية

1. يرى الموظف أسماء تنقل دقيقة ولا يرى `LIVE` إلا إذا ضبطت البيئة صراحةً بهذا الاسم.
2. لا يهيمن إنشاء الشحنة على صفحات المالية والتقارير والإعدادات.
3. لا ينهار أي محدد أو اسم ملف إلى عمود حرفي على الهاتف أو اللوحي.
4. يستطيع العميل الوصول للحساب المالي والملف الشخصي بوضوح.
5. لا يحدث overflow أفقي على الصفحات المتأثرة عند 390px و430px.

## معايير النجاح

- اجتياز PHP lint للملفات المعدلة.
- اجتياز اختبارات البوابة الحالية ذات الصلة.
- فحص بصري محلي للإدارة ثم البوابة على سطح المكتب والهاتف.
- عدم تغيير نتائج الملكية والبيانات والحسابات.
- تسجيل حالة Admin وPortal وMobile في التقرير وسجل التطابق.

## القيود الفنية

- تمديد Dolibarr القائم فقط، بلا تعديل Core.
- لا وصول أو تعديل إنتاجي.
- حماية التعديلات المحلية الحالية وعدم استخدام أوامر تنظيف مدمرة.
- التوقف عند أي تعارض مادي بدل استبدال عمل غير تابع للمهمة.

## المخاطر ومفهوم التراجع

- **المخاطر:** تأثير CSS المشترك على صفحة غير مفحوصة؛ تسمية بيئة خاطئة إن كانت القيمة غير مضبوطة.
- **التراجع:** استرجاع رقع M032 فقط من الملفات المسجلة في تقرير الإنجاز، دون المساس بتعديلات M030/M031 أو البيانات.

## متطلبات الاختبار

- PHP lint واختبارات الوحدة/العزل الحالية.
- فحص 390px و430px وسطح المكتب للصفحات المتأثرة.
- فحص عدم وجود تحذيرات PHP أو overflow أو عناصر أقل من 44px في الإجراءات الرئيسية.
- إعادة فحص forged `socid`/ملكية العميل إذا لمس التعديل مسارًا ديناميكيًا؛ وإلا توثيق عدم تغير المنطق.
